# 文章发布与归档

文章以 Markdown 文件保存在 `source/_posts`。每篇文章旁的“归档”链接只在本机预览显示，并会打开对应文章在 GitHub 上的源文件编辑页。公开网站不显示文章归档按钮和导航中的归档管理选项。

## 通过按钮归档

1. 在博客目录运行 `npm run server`，打开 `http://localhost:4000/` 本机预览；在 GitHub 登录有仓库写入权限的账号后，点击文章旁的“归档”。
2. 在对应文章的 YAML front matter 添加：

```yaml
archived: true
```

3. 提交更改。GitHub Actions 会重新构建并部署站点。

归档后，文章详情页会从公开站点移除，也不会出现在归档、分类、标签、站内搜索或 RSS/Atom Feed 中。文章源文件仍保留在仓库；取消归档时删除 `archived: true` 后重新提交即可。

## 权限说明

此站点是静态 GitHub Pages 页面，没有访客登录或写入接口。归档入口在生成的HTML中默认带有 `hidden`，仅在 `localhost`、`127.0.0.1` 或本机IPv6回环地址预览时显示，不使用可伪造的“我是作者”本地存储开关。线上所有访问者（包括作者本人）都不显示归档管理入口；作者可通过本机预览或直接进入GitHub编辑。

本机可见仅用于区分编辑环境，并非身份认证。真正的修改和提交仍由 GitHub 仓库权限控制。网页端没有存放访问令牌，也不能绕过 GitHub 权限。

如果要确保只有你本人能归档，请在 GitHub 仓库的访问设置中确认只有你的账号拥有写入/维护权限。没有仓库写入权限的访客无法直接提交归档更改。

也可以直接修改文章 Markdown：在 front matter 添加或删除 `archived: true` 后重新构建部署。归档过滤逻辑位于 `scripts/archive-posts.js`。
